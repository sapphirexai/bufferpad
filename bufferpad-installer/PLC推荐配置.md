# 缓冲垫项目 PLC 推荐配置

本文给出缓冲垫项目当前支持的三菱、汇川和西门子 PLC 的一套完整、可直接实施的推荐配置。每一套地址对应 **一个扫码器**；同一 PLC 可以服务多个扫码器，但各扫码器的地址段必须互不重叠。

> 本文中的 PLC 地址是“设置 -> PLC地址”页面的 `PLC端口/地址`，不是设备 IP 或网络端口。网络端口在“设置 -> 设备信息”中配置。

## 一、统一规则

| 编码 | 操作类型 | 系统动作 |
| ---: | --- | --- |
| `0` | 扫码失败 | 向对应地址写入 16 位整数 `1` |
| `1` | 扫码超过最大次数 | 向对应地址写入 16 位整数 `1` |
| `2` | 扫码成功 | 向对应地址写入 `1`；写入成功后，读取类型 `6` 的开口数 |
| `3` | 重新扫码超过最大次数 | 向对应地址写入 16 位整数 `1` |
| `4` | 重新扫码成功 | 向对应地址写入 `1`；写入成功后，读取类型 `7` 的开口数 |
| `5` | 心跳 | 系统每 2 秒向对应地址写入 16 位整数 `0` |
| `6` | 扫码成功开口数回读 | 从对应地址读取 16 位有符号整数 `INT` |
| `7` | 重新扫码成功开口数回读 | 从对应地址读取 16 位有符号整数 `INT` |

- 类型 `2`、`4` 的回读只会在类型 `6`、`7` 已配置时执行。
- PLC 程序收到通知值 `1` 后应自行消费并清零；心跳 `0` 不需要由 PLC 回写。
- 一个扫码器只能关联一台 PLC；同一扫码器的同一操作类型只能配置一条地址。
- PLC 与扫码器必须配置为相同产线。心跳在同一 PLC 上只配置一条即可。
- 开口数为业务数量，建议限定为 `0..32767`；三类 PLC 均按 16 位整数读写。

## 二、设备信息通信参数

| PLC 类型 | 设备类型编码 | 适用型号 | 后端通信方式 | 推荐端口 | 关键参数 |
| --- | ---: | --- | --- | ---: | --- |
| 三菱 PLC | `1` | MELSEC iQ-R / R 系列 | MC/SLMP over TCP | `3301` | PLC 侧开放 `SLMP连接设备 / SLMP / TCP` |
| 汇川 PLC | `2` | AM / AC 系列 | Inovance Modbus TCP | `502` | PLC 侧启用 Modbus TCP Server，站号 `1` |
| 西门子 S7 PLC | `3` | SIMATIC S7-1200 / S7-1500 | S7comm over ISO-on-TCP | `102` | `rack=0`、`slot=0` |

设备信息示例：

| 字段 | 三菱 R 系列 | 汇川 AM/AC | 西门子 S7-1200 / S7-1500 |
| --- | --- | --- | --- |
| 设备类型 | `三菱PLC` | `汇川PLC` | `西门子 S7 PLC` |
| 设备名称 | `1线-三菱主PLC` | `1线-汇川主PLC` | `1线-S7主PLC` |
| IP | `192.0.2.12` | `192.0.2.13` | `192.0.2.14` |
| 端口 | `3301` | `502` | `102` |
| 产线 | `1` | `1` | `1` |
| 安装位置 | `PLC柜` | `PLC柜` | `PLC柜` |

西门子 S7-1200 和 S7-1500 使用同一个设备类型 `西门子 S7 PLC（3）`，不需要分开配置，也不要再选择历史类型 `4`。

## 三、三菱 MELSEC iQ-R / R 系列推荐配置

### 通信前提

在 GX Works3 的以太网/外部设备配置中建立或启用 `SLMP连接设备`：通信手段选择 `SLMP`，协议选择 `TCP`，端口设为 `3301`。将参数写入 PLC 后，按现场流程复位或重启 PLC；后端电脑应能通过 `Test-NetConnection <PLC_IP> -Port 3301` 访问该端口。

### 推荐地址配置

| 编码 | 操作类型 | 地址 | 动作 |
| ---: | --- | --- | --- |
| `0` | 扫码失败 | `D6600` | 写入 `1` |
| `1` | 扫码超过最大次数 | `D6601` | 写入 `1` |
| `2` | 扫码成功 | `D6602` | 写入 `1`，随后读取类型 `6` |
| `3` | 重新扫码超过最大次数 | `D6603` | 写入 `1` |
| `4` | 重新扫码成功 | `D6604` | 写入 `1`，随后读取类型 `7` |
| `5` | 心跳 | `D6605` | 每 2 秒写入 `0` |
| `6` | 扫码成功开口数回读 | `D6606` | 读取 16 位整数 |
| `7` | 重新扫码成功开口数回读 | `D6607` | 读取 16 位整数 |

第二个扫码器应使用另一段不重叠的 D 寄存器，例如从 `D6616` 开始。最终寄存器范围仍以 PLC 工程师确认的点位表和 PLC 参数为准。

## 四、汇川 AM / AC 系列推荐配置

### 通信前提

在汇川 PLC 工程中启用 Modbus TCP Server，端口设为 `502`，站号（Unit ID）设为 `1`。后端当前连接器固定使用站号 `1`；若现场 PLC 使用其他站号，应先调整后端配置/代码后再上线。后端电脑应能通过 `Test-NetConnection <PLC_IP> -Port 502` 访问该端口。

### 推荐地址配置

| 编码 | 操作类型 | 地址 | 动作 |
| ---: | --- | --- | --- |
| `0` | 扫码失败 | `MW10000` | 写入 `1` |
| `1` | 扫码超过最大次数 | `MW10001` | 写入 `1` |
| `2` | 扫码成功 | `MW10002` | 写入 `1`，随后读取类型 `6` |
| `3` | 重新扫码超过最大次数 | `MW10003` | 写入 `1` |
| `4` | 重新扫码成功 | `MW10004` | 写入 `1`，随后读取类型 `7` |
| `5` | 心跳 | `MW10005` | 每 2 秒写入 `0` |
| `6` | 扫码成功开口数回读 | `MW10006` | 读取 16 位整数 |
| `7` | 重新扫码成功开口数回读 | `MW10007` | 读取 16 位整数 |

第二个扫码器应使用另一段不重叠的 MW 寄存器，例如从 `MW10016` 开始。本文仅适用于 AM/AC 系列的 `MW` 地址模型；H5U/EASY 等使用 `D`、`R` 寄存器模型的汇川 PLC，需先确认驱动和地址模型。

## 五、西门子 SIMATIC S7-1200 / S7-1500 推荐配置

### 通信前提

在 TIA Portal 中完成以下配置：

1. CPU 允许来自远程伙伴的 PUT/GET 通信。
2. CPU 的保护等级和访问权限允许外部读取、写入。
3. 用于绝对地址的 `DB100` 关闭“优化的块访问”，重新编译并下载到 PLC。
4. 后端电脑可以通过 `Test-NetConnection <PLC_IP> -Port 102` 访问 TCP `102`。
5. `DB100` 中以下变量声明为 TIA `INT`。`DBW` 后的数字为**字节偏移**，所以 16 位字按 `0、2、4...` 分配。

### 推荐地址配置

S7-1200、S7-1500 都可以使用下面这组配置：

| 编码 | 操作类型 | 地址 | 动作 |
| ---: | --- | --- | --- |
| `0` | 扫码失败 | `DB100.DBW0` | 写入 `1` |
| `1` | 扫码超过最大次数 | `DB100.DBW2` | 写入 `1` |
| `2` | 扫码成功 | `DB100.DBW4` | 写入 `1`，随后读取类型 `6` |
| `3` | 重新扫码超过最大次数 | `DB100.DBW6` | 写入 `1` |
| `4` | 重新扫码成功 | `DB100.DBW8` | 写入 `1`，随后读取类型 `7` |
| `5` | 心跳 | `DB100.DBW10` | 每 2 秒写入 `0` |
| `6` | 扫码成功开口数回读 | `DB100.DBW12` | 读取 `INT` |
| `7` | 重新扫码成功开口数回读 | `DB100.DBW14` | 读取 `INT` |

第二个扫码器建议从 `DB100.DBW32` 开始预留另一段地址。不要使用 `DBX`、`MX` 等位地址；输入区 `IWoffset` 只适合作为开口数回读地址，不能配置为写入通知或心跳地址。

## 六、现场配置与验收步骤

1. 在“设备安装位置”中先建立 `PLC柜` 等位置。
2. 在“设备信息”新增扫码器和相应 PLC，确保二者产线一致并按上表填写通信端口。
3. 在“PLC地址”中针对一个扫码器，逐条选择相同的 PLC 并录入本型号的 0 至 7 类型地址；心跳只保留一条。
4. 刷新运行页面，确认扫码器和 PLC 均在线。
5. 用测试码 `[TPL_STX]TEST-001[TPL_ETX]` 扫码，确认 PLC 收到类型 `2` 的值 `1`，且系统成功读取类型 `6` 的开口数。
6. 测试 `NoRead`、超过寿命和手动重扫，分别确认类型 `0`、`1`、`3`、`4`、`7` 的地址行为。

如果 PLC 未收到信号，优先核对设备 IP/端口、PLC 通信服务、扫码器与 PLC 的产线、地址是否属于当前扫码器，以及 PLC 程序是否已下载生效。不要为补偿 PLC 通信失败而重复扫码，以免缓冲垫使用次数重复增加。

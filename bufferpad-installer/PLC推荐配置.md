# 缓冲垫项目 PLC 推荐配置

本文给出缓冲垫项目当前支持的三菱、汇川和西门子 PLC 的一套完整、可直接实施的推荐配置。每一套地址对应 **一个扫码器**；同一 PLC 可以服务多个扫码器，但各扫码器的地址段必须互不重叠。

> 本文中的 PLC 地址是“设置 -> PLC地址”页面的 `PLC端口/地址`，不是设备 IP 或网络端口。网络端口在“设置 -> 设备信息”中配置。

## 一、统一规则

| 编码 | 操作类型 | 系统动作 |
| ---: | --- | --- |
| `0` | 扫码失败 | 向对应地址写入 16 位整数 `1` |
| `1` | 扫码超过最大次数 | 向对应地址写入 16 位整数 `1` |
| `2` | 扫码成功 | 向对应地址写入 `1`；写入成功后，读取类型 `6` 的开口数 |
| `3` | 重新扫码超过最大次数 | 向对应地址写入 16 位整数 `1` |
| `4` | 重新扫码成功 | 向对应地址写入 `1`；写入成功后，读取类型 `7` 的开口数 |
| `5` | 心跳 | 系统每 2 秒向对应地址写入 16 位整数 `0` |
| `6` | 扫码成功开口数回读 | 从对应地址读取 16 位有符号整数 `INT` |
| `7` | 重新扫码成功开口数回读 | 从对应地址读取 16 位有符号整数 `INT` |

- 类型 `2`、`4` 的回读只会在类型 `6`、`7` 已配置时执行。
- PLC 程序收到通知值 `1` 后应自行消费并清零；心跳 `0` 不需要由 PLC 回写。
- 一个扫码器只能关联一台 PLC；同一扫码器的同一操作类型只能配置一条地址。
- PLC 与扫码器必须配置为相同产线。心跳在同一 PLC 上只配置一条即可。
- 开口数为业务数量，建议限定为 `0..32767`；三类 PLC 均按 16 位整数读写。

## 二、设备信息通信参数

| PLC 类型 | 设备类型编码 | 适用型号 | 后端通信方式 | 推荐端口 | 关键参数 |
| --- | ---: | --- | --- | ---: | --- |
| 三菱 PLC | `1` | MELSEC iQ-R / R 系列 | MC/SLMP over TCP | `3301` | PLC 侧开放 `SLMP连接设备 / SLMP / TCP` |
| 汇川 PLC | `2` | AM / AC 系列 | Inovance Modbus TCP | `502` | PLC 侧启用 Modbus TCP Server，站号 `1` |
| 西门子 S7 PLC | `3` | SIMATIC S7-1200 / S7-1500 | S7comm over ISO-on-TCP | `102` | `rack=0`、`slot=0` |

设备信息示例：

| 字段 | 三菱 R 系列 | 汇川 AM/AC | 西门子 S7-1200 / S7-1500 |
| --- | --- | --- | --- |
| 设备类型 | `三菱PLC` | `汇川PLC` | `西门子 S7 PLC` |
| 设备名称 | `1线-三菱主PLC` | `1线-汇川主PLC` | `1线-S7主PLC` |
| IP | `192.0.2.12` | `192.0.2.13` | `192.0.2.14` |
| 端口 | `3301` | `502` | `102` |
| 产线 | `1` | `1` | `1` |
| 安装位置 | `PLC柜` | `PLC柜` | `PLC柜` |

西门子 S7-1200 和 S7-1500 使用同一个设备类型 `西门子 S7 PLC（3）`，不需要分开配置，也不要再选择历史类型 `4`。

## 三、三菱 MELSEC iQ-R / R 系列推荐配置

### 工程与通信配置

三菱 R 系列 PLC 必须在 GX Works3 中打开 MC/SLMP 的 TCP 通信端口。建议在内置以太网/外部设备配置中建立或启用 `SLMP连接设备`，并按下表配置：

| 项目 | 推荐值 |
| --- | --- |
| 型号 | `SLMP连接设备` |
| 通信手段 | `SLMP` |
| 协议 | `TCP`，不要选择 `UDP` |
| 可编程控制器 IP 地址 | PLC 自己的 IP，例如 `192.0.2.12` |
| 可编程控制器端口号 | `3301` |

完成参数编辑后，依次执行“反映设置并关闭”->“应用”->“在线 -> 写入至可编程控制器”，再按现场流程复位或断电重启 PLC。后端电脑应能通过 `Test-NetConnection <PLC_IP> -Port 3301` 访问该端口。

特别注意：在 GX Works3 中必须允许 MC/SLMP 外部设备在 PLC **运行时写入寄存器**。若工程存在“运行中禁止写入”“无法在运行时间内写入”或同义限制，应取消该限制；随后重新将参数写入 PLC，并按要求复位或重启。该项曾是现场 TCP 已连接但后端无法通知三菱 PLC 的直接原因。

### 推荐地址配置

| 编码 | 操作类型 | 地址 | 动作 |
| ---: | --- | --- | --- |
| `0` | 扫码失败 | `D6600` | 写入 `1` |
| `1` | 扫码超过最大次数 | `D6601` | 写入 `1` |
| `2` | 扫码成功 | `D6602` | 写入 `1`，随后读取类型 `6` |
| `3` | 重新扫码超过最大次数 | `D6603` | 写入 `1` |
| `4` | 重新扫码成功 | `D6604` | 写入 `1`，随后读取类型 `7` |
| `5` | 心跳 | `D6605` | 每 2 秒写入 `0` |
| `6` | 扫码成功开口数回读 | `D6606` | 读取 16 位整数 |
| `7` | 重新扫码成功开口数回读 | `D6607` | 读取 16 位整数 |

### 现场要求

- `D6600` 至 `D6607` 为一个扫码器的推荐信号字；每个 D 寄存器均按 16 位整数处理，开口数建议限制在 `0..32767`。
- PLC 程序消费类型 `0` 至 `4` 的通知值 `1` 后应主动清零，避免现场逻辑持续把同一事件视为有效。
- 类型 `2`、`4` 写成功后，系统会立即读取类型 `6`、`7`；PLC 应持续维护 `D6606`、`D6607` 的最新开口数。
- 第二个扫码器建议从 `D6616` 开始，为每个扫码器预留 16 个 D 字（32 字节），各地址段不得重叠。
- 本项目三菱 R 系列推荐使用 `D` 数据寄存器，不要将位设备 `M`、`X`、`Y` 或其他型号的地址格式填入 PLC 地址页面。
- 若后端报 `Connection refused`，优先检查是否确实配置在 `SLMP连接设备`、协议是否为 TCP、参数是否已写入 PLC，以及 PLC 是否已复位/重启。
- 后端已连通但写入被 PLC 拒绝时，优先复查“运行时写入”权限：MC/SLMP 外部设备必须允许 PLC 运行中写入，不能保留“运行中禁止写入/无法在运行时间内写入”限制。

## 四、汇川 AM / AC 系列推荐配置

### 工程与通信配置

在汇川 AM/AC PLC 工程中启用 Modbus TCP Server，并确认后端所在网段可以访问 PLC。推荐参数如下：

| 项目 | 推荐值 |
| --- | --- |
| 通信方式 | Modbus TCP Server |
| TCP 端口 | `502` |
| 站号（Unit ID） | `1` |
| 可访问寄存器 | `MW` 保持寄存器 |
| 网络限制 | 允许后端服务器 IP 访问，不阻断 TCP `502` |

后端当前连接器固定使用站号 `1`；若现场 PLC 使用其他站号，应先调整后端配置/代码后再上线。后端电脑应能通过 `Test-NetConnection <PLC_IP> -Port 502` 访问该端口。

### 推荐地址配置

| 编码 | 操作类型 | 地址 | 动作 |
| ---: | --- | --- | --- |
| `0` | 扫码失败 | `MW10000` | 写入 `1` |
| `1` | 扫码超过最大次数 | `MW10001` | 写入 `1` |
| `2` | 扫码成功 | `MW10002` | 写入 `1`，随后读取类型 `6` |
| `3` | 重新扫码超过最大次数 | `MW10003` | 写入 `1` |
| `4` | 重新扫码成功 | `MW10004` | 写入 `1`，随后读取类型 `7` |
| `5` | 心跳 | `MW10005` | 每 2 秒写入 `0` |
| `6` | 扫码成功开口数回读 | `MW10006` | 读取 16 位整数 |
| `7` | 重新扫码成功开口数回读 | `MW10007` | 读取 16 位整数 |

### 现场要求

- `MW10000` 至 `MW10007` 为一个扫码器的推荐 16 位字地址；开口数建议限制在 `0..32767`。
- PLC 程序消费类型 `0` 至 `4` 的通知值 `1` 后应主动清零；类型 `2`、`4` 写成功后，系统会立即读取类型 `6`、`7`，因此 PLC 应持续维护 `MW10006`、`MW10007` 的最新开口数。
- 第二个扫码器建议从 `MW10016` 开始，为每个扫码器预留 16 个 MW 字（32 字节），各地址段不得重叠。
- 本项目“汇川PLC”类型只按 AM/AC 的 `MW` 地址模型配置。H5U/EASY 等使用 `D`、`R` 的机型，或使用线圈/位地址的方案，必须先确认后端驱动是否支持，不能直接套用本文地址。
- Modbus TCP 端口可达但读写失败时，检查 PLC 是否已启用 Modbus TCP Server、站号是否为 `1`、`MW10000` 地址段是否已映射/允许远程访问，以及现场网络是否有 IP 白名单或防火墙限制。

## 五、西门子 SIMATIC S7-1200 / S7-1500 推荐配置

### 工程与通信配置

在 TIA Portal 中完成以下配置：

1. CPU 允许来自远程伙伴的 PUT/GET 通信。
2. CPU 的保护等级和访问权限允许外部读取、写入。
3. 用于绝对地址的 `DB100` 关闭“优化的块访问”，重新编译并下载到 PLC。
4. 后端电脑可以通过 `Test-NetConnection <PLC_IP> -Port 102` 访问 TCP `102`。
5. `DB100` 中以下变量声明为 TIA `INT`。`DBW` 后的数字为**字节偏移**，所以 16 位字按 `0、2、4...` 分配。

### 推荐地址配置

S7-1200、S7-1500 都可以使用下面这组配置：

| 编码 | 操作类型 | 地址 | 动作 |
| ---: | --- | --- | --- |
| `0` | 扫码失败 | `DB100.DBW0` | 写入 `1` |
| `1` | 扫码超过最大次数 | `DB100.DBW2` | 写入 `1` |
| `2` | 扫码成功 | `DB100.DBW4` | 写入 `1`，随后读取类型 `6` |
| `3` | 重新扫码超过最大次数 | `DB100.DBW6` | 写入 `1` |
| `4` | 重新扫码成功 | `DB100.DBW8` | 写入 `1`，随后读取类型 `7` |
| `5` | 心跳 | `DB100.DBW10` | 每 2 秒写入 `0` |
| `6` | 扫码成功开口数回读 | `DB100.DBW12` | 读取 `INT` |
| `7` | 重新扫码成功开口数回读 | `DB100.DBW14` | 读取 `INT` |

### 现场要求

- `DB100` 必须关闭“优化的块访问”；使用绝对 DB 地址后，要重新编译并下载 PLC 工程。
- CPU 必须允许远程 PUT/GET 通信，且保护等级、访问权限允许外部读取和写入。
- `DB100` 中上述变量均声明为 TIA `INT`，开口数范围建议为 `0..32767`。
- `DBW` 后的数字是字节偏移；16 位变量按 `0、2、4...` 分配，不能让两个变量重叠。
- PLC 消费通知值 `1` 后应主动清零；类型 `2`、`4` 写成功后系统会立即读取类型 `6`、`7`，因此 PLC 应持续维护最新开口数。
- 第二个扫码器建议从 `DB100.DBW32` 开始，为每个扫码器预留 32 字节，地址段不得重叠。
- 不要使用 `DBX`、`MX` 等位地址；输入区 `IWoffset` 只适合作为开口数回读地址，不能配置为写入通知或心跳地址。
- 标准 CPU 网口按 `rack=0`、`slot=0` 连接；TCP `102` 可达但读写失败时，依次检查 PUT/GET、DB 非优化访问、CPU 权限和工程下载状态。

## 六、运行中写入被拒绝的通用排查

“端口可达”只说明网络连通，不代表 PLC 接受业务写入。三种 PLC 都可能因工程侧权限、寄存器访问范围或运行模式拒绝写入，但具体设置不同：

| PLC 类型 | 优先检查项 |
| --- | --- |
| 三菱 R 系列 | GX Works3 的 `SLMP连接设备` 是否为 TCP；是否取消“运行中禁止写入/无法在运行时间内写入”限制；修改后是否已写入 PLC 并复位或重启。 |
| 汇川 AM/AC | Modbus TCP Server 是否启用，站号是否为 `1`，`MW` 地址段是否允许远程读写，以及是否存在 IP 白名单/防火墙限制。 |
| 西门子 S7-1200/S7-1500 | PUT/GET 是否允许、CPU 保护等级是否允许外部读写、目标 DB 是否关闭优化访问，以及工程是否已下载生效。 |

## 七、现场配置与验收步骤

1. 在“设备安装位置”中先建立 `PLC柜` 等位置。
2. 在“设备信息”新增扫码器和相应 PLC，确保二者产线一致并按上表填写通信端口。
3. 在“PLC地址”中针对一个扫码器，逐条选择相同的 PLC 并录入本型号的 0 至 7 类型地址；心跳只保留一条。
4. 刷新运行页面，确认扫码器和 PLC 均在线。
5. 用测试码 `[TPL_STX]TEST-001[TPL_ETX]` 扫码，确认 PLC 收到类型 `2` 的值 `1`，且系统成功读取类型 `6` 的开口数。
6. 测试 `NoRead`、超过寿命和手动重扫，分别确认类型 `0`、`1`、`3`、`4`、`7` 的地址行为。

如果 PLC 未收到信号，优先核对设备 IP/端口、PLC 通信服务、扫码器与 PLC 的产线、地址是否属于当前扫码器，以及 PLC 程序是否已下载生效。不要为补偿 PLC 通信失败而重复扫码，以免缓冲垫使用次数重复增加。

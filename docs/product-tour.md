# BufferPad 图文导览

[返回首页](../README.md) · [开始部署](getting-started.md)

BufferPad 面向使用可重复利用缓冲垫的制造现场：扫描编号、记录使用次数、根据寿命阈值提示，并与已配置的 PLC 联动。下面展示运行监控与设备诊断界面，不需要先安装软件即可了解操作方式。

截图由维护者提供，保留拍摄时的数据和状态；现场地址在公开副本中遮盖。截图不是实时演示，也不构成特定设备型号已通过验收的声明。

## 1. 运行监控与寿命查询

![运行监控页：产线选择、扫码状态、寿命阈值和使用记录](images/runtime-monitor.png)

- **先选择产线**：顶部汇总该产线 PLC、读码器的连接及故障情况。
- **等待扫码或手工输入**：界面提示当前扫码状态，操作人员可以查看当前缓冲垫信息。
- **查看寿命**：列表显示编号、位置、首次/最后使用时间、当前次数和使用寿命。图中阈值为 95%，这是截图中的配置值，并非所有部署的固定值。
- **追溯使用情况**：通过搜索、明细、日志查询及导出入口调查使用记录。

扫码计数和 PLC 联动受实际配置及业务规则影响；重复扫码不应简单理解为每次都会累加。

## 2. PLC 连接与故障诊断

![PLC 设备抽屉：连接、通信验证和连续超时状态](images/plc-status.png)

点击“查看设备”并进入 PLC 标签，可以查看单台设备的类型、连接状态、检测方式、更新时间和最近请求结果。

截图刻意保留故障状态，展示系统如何解释问题：上方三台设备提示通信超时；下方设备虽然 TCP 已连接，仍显示通信未验证。**TCP 连接成功不等于业务读写成功。** 实际定位问题时应结合检测方式、请求记录和设备配置。

## 3. 读码器连接与待机状态

![读码器设备抽屉：TCP 连接与被动接收状态](images/scanner-status.png)

切换到“读码器”标签可查看各扫码器状态。截图中的设备采用被动接收方式：已连接但尚无通信验证结果时，可以处于正常待机状态，不应仅因未收到条码就判为故障。

## 从图文了解走向实际部署

1. 阅读[快速开始](getting-started.md)，准备 Java、Node、MySQL 和 HSL 本地依赖。
2. 按[构建与打包](build-and-package.md)准备应用；Windows 安装脚本不会自动获得 HSL 授权。
3. 在隔离测试环境配置设备并核对读写行为，参考[设备配置说明](../bufferpad-installer/设备配置说明.md)。

当前没有在线演示或一键模拟设备模式；本页提供图文介绍。视频演示不在本轮交付范围内。

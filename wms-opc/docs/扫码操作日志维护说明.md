# 扫码操作日志维护说明

**简体中文** · [English](scan-operation-logs.en.md) · [文档目录](../../docs/README.md)

## 行为

从本版本起，`scan_log` 以 `operation_id` 汇总一次操作。自动扫码每次接收生成独立操作；同二维码两小时内再次扫描仍有新日志，但沿用原有计数去重规则。同一 operation_id 重复提交不会重复执行业务。同一操作的扫码、计数、PLC通知、开口数回读在同一行合并更新。

`msg` 包含操作来源、结果、二维码、产线、扫码/计数结果、当前次数和上限、扫码器与PLC名称/ID/IP/端口/位置、PLC地址及结果、回读结果；手动扫码还包括当前登录用户名。未确定的设备明确写未关联或未配置，不猜测。设备快照取首次关联时信息，因此同名同IP不同ID/位置仍能区分，后来改名不会改写历史快照。

| 状态 | 含义 |
| --- | --- |
| 处理中 | 某个必要阶段还没有结果 |
| 成功 | 必要阶段全部完成 |
| 提示 | 重复扫码、达到/超过寿命，或计数完成但缺少配置/回读失败等 |
| 失败 | 未识别二维码、计数事务回滚、PLC写入失败或拒绝等；具体已成功阶段仍明确保留 |
| 结果未知 | 超过5分钟未完成，或无法确认业务结果，需要核实 |
| 历史日志 | 升级前的记录，不补造当时的设备或阶段信息 |

每分钟检查最多1000条超时处理中记录。该任务只更新日志，不重发PLC、不补加次数。迟到的真实结果可更新原行。独立PLC回读标记为独立PLC操作；应用诊断日志和原有运行事件继续保留，心跳、连接重试不刷扫码主日志。

日志页默认20条；结果、扫码器、PLC可组合筛选。设备输入纯数字时按设备ID精确查询，其他文字按历史快照匹配名称、IP、位置。长消息列表显示摘要，可点“查看详情”。旧记录没有设备字段，使用原有二维码、内容、时间筛选。

## 数据库升级与安装

先完成原有旧库结构升级，再执行 `docs/sql/20260914_scan_log_operation_summary.sql`。脚本面向 MySQL 8.0，已在8.0.45隔离环境和8.0.42生产执行。脚本保留旧行，新增可空字段及索引，将 `msg` 改为 `TEXT`，保留空字符串默认值；可重复执行。

VARCHAR转TEXT需要COPY重建表。执行前备份scan_log并验证备份、检查磁盘空间，暂停本项目后端写入，然后执行脚本、启动新版后端并发布新版前端。不能只替换JAR而跳过迁移。本版本不会在后端启动时自动执行大表DDL。

Windows安装包已同步迁移；`prepare-app.ps1` 同步制品，安装程序按名称顺序运行全部迁移。Docker Compose部署需按上述顺序显式执行迁移。新增列和TEXT兼容上一版本写入，应用回退时保留新结构，不自动覆盖生产日志表。

日志保留任务仍按既定规则每天03:00分批清理三个月前记录。为保留审计记录，扫码入口若无法写入初始日志会终止该次操作并报错；操作开始后的汇总更新异常写应用错误日志，超过时限仍未完成的记录标记结果未知。

## 验证入口

- 后端回归：使用项目可用Maven settings执行 `mvn test` / `mvn package`。
- `ScanOperationLogServiceTest`：行锁合并、阶段顺序、重复事件、设备快照、回滚及超时。
- `ScanSummaryMysqlAcceptance`：仅允许loopback的专用验收库，实际MySQL+Druid并发、长消息、独立事务、清理兼容。
- 工作区 `tmp/test-scan-summary.py`：完整隔离验收，实际TCP扫码器和Modbus模拟器，默认不访问生产设备。

本次发布结果、备份和测试范围见根目录《扫码操作日志汇总验收报告》。

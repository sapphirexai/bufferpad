# 日志分页查询

`GET /scanLogs` 改为数据库分页，默认 `currentPage=1&pageSize=20`。原有二维码、日志内容、日志类型、起止时间筛选继续生效，单独填写起始或结束时间也会生效。按 `created_date DESC, id DESC` 排序，同一时间的记录按 ID 稳定排序。

响应 `data` 由原来的数组改为与现有列表页一致的分页对象：

```json
{
  "currentPage": 1,
  "pageSize": 20,
  "totalPage": 1000000,
  "data": []
}
```

这里 `totalPage` 沿用项目已有约定，表示符合筛选的总记录数，不是总页数。前端与后端须配套更新。普通用户、管理员均可查询，匿名请求仍返回 401。

服务端将非正数页码归为第 1 页，非正数每页条数归为 20，单页上限为 200，防止负数参数关闭 MyBatis-Plus 分页。前端默认 20 条，可选择 20、50、100 条；重新查询或切换每页条数时回到第一页，过期请求不能覆盖新查询结果。

不需要数据库结构变更，也不需要重新执行旧库升级 SQL。保留现有日志记录。分页避免将所有匹配日志装入 Java 内存，但总数统计及无索引的筛选、排序仍会消耗数据库资源；本次没有在线给日志大表创建索引。

验证：`ScanLogPaginationTest` 使用真实 Mapper 与分页拦截器，覆盖分页边界、排序、参数限制及筛选；前端 `log-pagination.spec.js` 覆盖翻页、筛选重置、空结果、错误和异步请求顺序。另在隔离 MySQL 百万日志上验证真实后端，详见工作区 `日志分页查询验收.md`。

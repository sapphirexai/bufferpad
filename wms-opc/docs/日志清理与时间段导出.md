# 日志保留和缓冲垫时间段导出

运行监控页提供“勾选导出”和“时间段导出”。后者选择第一次使用时间或最后一次使用时间（默认），选择起止日期及时间后导出 XLSX。每块缓冲垫一行，包含其当前信息，导出全部匹配记录，不受当前分页、勾选和搜索条件限制。开始秒和结束秒均包含；没有记录或超过 100000 条会提示调整范围。普通用户和管理员均有查询及导出权限。

## 日志清理

每天北京时间 03:00 按 `scan_log.created_date` 删除执行当天零点向前推三个自然月之前的记录。截止时间本身保留。例如 2026-09-15 执行时，删除早于 2026-06-15 00:00:00 的日志。保留期按日计算；最多会比精确三个月多保留不到一天。不影响 `cushion_detail` 和 `cushion_info`。

默认每批 1000 条、独立提交、批间等待 100 毫秒，一次运行的批次启动时间预算为 300 秒。已启动的单批可能再等待至查询超时（10 秒）。达到预算后剩余过期日志留到下次执行；数据积压很多时可能需要多个夜间任务才能全部清完。多实例通过数据库命名锁互斥，失败后下次重试，并记录截止时间、已删数量、批次和状态。

必须先备份 `scan_log`，然后执行 `docs/sql/20260914_scan_log_retention_index.sql`。该文件只建索引，不删数据；可重复执行，只支持 MySQL 8.0 在线加索引，失败不会退回整表复制。缺少以 `created_date` 开头的索引时，清理任务跳过并记录错误。旧库升级 SQL 不自动增加此索引，升级完成后另行执行此迁移。Windows 安装程序已携带相同迁移。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `SCAN_LOG_RETENTION_ENABLED` | `true` | 是否清理；关闭后重启服务生效 |
| `SCAN_LOG_RETENTION_MONTHS` | `3` | 保留自然月数 |
| `SCAN_LOG_RETENTION_ZONE` | `Asia/Shanghai` | 截止日期与调度时区 |
| `SCAN_LOG_CLEANUP_CRON` | `0 0 3 * * ?` | 每天 03:00 |
| `SCAN_LOG_CLEANUP_BATCH_SIZE` | `1000` | 单批数量，最多 10000 |
| `SCAN_LOG_CLEANUP_MAX_SECONDS` | `300` | 批次启动时间预算 |
| `SCAN_LOG_CLEANUP_PAUSE_MILLIS` | `100` | 批间停顿 |

启动应用不会立即清理；部署到 149 时保持上述默认值，等待下一次 03:00。查看应用日志中的 `scan_log cleanup completed` 或 `scan_log cleanup task failed`。遇到索引缺失、锁占用或数据库错误，应按日志原因处理；不要用无条件 `DELETE` 或 `TRUNCATE` 替代任务。

## 导出接口

`POST /cushion/cushions/excel/time-range`，需要有效登录和 CSRF 请求头。请求示例：

```json
{
  "timeType": "LAST_USE",
  "startTime": "2026-09-01 00:00:00",
  "endTime": "2026-09-14 23:59:59"
}
```

`FIRST_USE` 对应 `created_date`，`LAST_USE` 对应 `last_scan_date`。数据库时间按北京时间解释和展示。成功返回完整 XLSX，参数、空结果及超限返回 HTTP 400 JSON。每批读取 1000 条，同一只读事务保证导出期间数据快照一致。生成或下载结束后删除临时文件；生成失败不会向用户返回半个 Excel。

## 验证入口

- 后端：`mvn test`，包括自然月、时区、并发、失败重试和时间参数校验。
- 前端：`npm run unit`，包括两种时间选择、空范围、重复提交、错误和下载认证处理。
- 真实 MySQL 验收：`src/test/java/cn/tpl/opc/infrastructure/maintenance/RetentionExportMysqlAcceptance.java` 为显式执行入口，只连接 loopback 的 `retention_export_acceptance` 测试库；由工作区 `tmp/test-retention-export.py` 创建夹具并调用。禁止改成生产地址运行。
